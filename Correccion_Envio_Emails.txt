CORRECCION DEL ENVIO DE CORREOS - POLI RENT
=============================================

1. EL PROBLEMA
---------------
En la computadora (local) los correos SI llegaban.
Al subir el proyecto a Render (produccion), los correos DEJARON de
llegar, y no se mostraba ningun error.


2. QUE ESTABA PASANDO (2 problemas, uno despues del otro)
-----------------------------------------------------------

PROBLEMA 1: Render no deja salir correos por la puerta que usabamos
   El proyecto mandaba los correos por "SMTP" (puerto 587), que es
   como una puerta especifica de salida a internet. Render tiene esa
   puerta cerrada para evitar spam. Por eso el correo nunca salia.

   DIAGRAMA - ANTES:

   [Backend en Render] --(puerto 587, SMTP)--> [ X ] Render bloquea
                                                       |
                                                       v
                                              Brevo nunca recibe nada
                                              = correo nunca sale


   DIAGRAMA - AHORA:

   [Backend en Render] --(puerto 443, HTTPS)--> [Brevo API] --> Correo enviado
                          (esta puerta SIEMPRE esta abierta,
                           es la misma que usa cualquier pagina web)


PROBLEMA 2: El remitente no estaba autorizado
   Brevo (el servicio que manda los correos) exige que el correo que
   aparece como "remitente" este verificado por ellos. El que se
   estaba usando NO estaba verificado, asi que Brevo lo rechazaba.

   Se busco en el panel de Brevo cual correo SI esta verificado
   (diegouu2512@gmail.com) y se uso ese en su lugar.


3. RESULTADO
-------------
Se probo registrando un usuario real en producción y el correo de
"Confirmar cuenta" llego correctamente, con el link funcionando.


4. VARIABLES: QUE PUSO EL INGENIERO VS. QUE SE AGREGO
--------------------------------------------------------

El ingeniero configuro variables pensando en mandar correo por SMTP
(la puerta que Render bloquea):

   HOST_MAILTRAP, PORT_MAILTRAP, PASS_MAILTRAP
   -> Ya no se usan, porque ya no mandamos correo por esa puerta.
      No estorban si se dejan, simplemente no hacen nada.

   USER_MAILTRAP
   -> Se sigue usando, pero ahora guarda otra cosa: antes era el
      usuario para esa puerta SMTP, ahora guarda el correo
      remitente verificado (diegouu2512@gmail.com).

VARIABLE NUEVA QUE SE AGREGO:

   BREVO_API_KEY
   -> Necesaria porque ahora se manda el correo por una via distinta
      (la API de Brevo), y esa via pide una clave diferente a la
      contrasena de SMTP que ya tenian. Se consigue en Brevo, en
      Configuracion > SMTP y API > "Claves API y MCP".


EN RESUMEN PARA LA PRESENTACION:
   El ingeniero dejo todo listo para mandar correo por SMTP.
   Se descubrio que Render bloquea esa via, asi que se cambio a una
   via distinta (API de Brevo). Por eso fue necesario agregar una
   variable nueva (BREVO_API_KEY) y cambiar el valor de una que ya
   existia (USER_MAILTRAP), porque la via nueva funciona distinto.
